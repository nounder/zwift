# zwift

A macOS Zig/SwiftUI interop playground, now targeting **Zig 0.16.0**.

## SwiftUI applications without swiftc

**ZwiftNative** builds and launches a Zig-defined SwiftUI `View` and `App`.
Zig emits their type metadata, conformance descriptors, associated body types,
ARM64 entrypoints and the call to SwiftUI's `App.main`. The application build
compiles no Swift source and links no precompiled application Swift objects.
It links Apple's existing Swift runtime and SwiftUI frameworks.

```sh
./scripts/zig build run-lab-native                    # build and open the app
./scripts/zig build lab-native-test                   # runtime metadata + real window
./scripts/zig build lab-native-test -Doptimize=ReleaseFast
./scripts/zig build lab-native-no-swift-test           # fresh caches; Swift compilers denied
./scripts/zig build lab-native-no-swift-test -Doptimize=ReleaseFast
./scripts/zig build lab-native-oracle                 # optional swiftc development check
./scripts/zig build run-lab-Animations                # SwiftUI TimelineView + Canvas
./scripts/zig build run-lab-Paint                     # drawing through a Zig NSViewRepresentable
./scripts/zig build lab-native-examples               # build all three native apps
./scripts/zig build lab-native-examples-test          # model, rendering, input and lifetime tests
./scripts/zig build lab-native-examples-test -Doptimize=ReleaseFast
```

The input is [lab/native/program.zig](lab/native/program.zig); the backend is
[lab/native/emitter.zig](lab/native/emitter.zig). `lab-native` installs
`zig-out/ZwiftNative.app` and an inspectable `zig-out/lab/native/NativeApp.s`.
The oracle is **not** a dependency of the native build or launch tests.

**ZwiftAnimations** uses SwiftUI's animation timeline and canvas, with Zig drawing
translation, rotation, scaling and fading. Its escaping renderer captures are
Swift heap objects emitted by Zig, with copy/destruction tests. These are
frame-driven animations; implicit `withAnimation`/`@State` transitions are still
outside the native backend's supported specializations.

**ZwiftPaint** provides strokes, colors, brush width, an eraser, undo/redo and
clear. Zig emits the `NSViewRepresentable` conformance and implements the AppKit
view, input handlers and per-view drawing state. SwiftUI creates the window and
calls make/update/dismantle. Tests send mouse and keyboard events through the
real window, check rendered pixels, and verify model release after window close.
Drawings are in memory. Cmd-Z and Cmd-Shift-Z undo and redo.

All three use a Zig-emitted `App.Body = WindowGroup<Root>`. The compiler-denial
test cold-builds and launches **all three**. Assembly copies are installed in
`zig-out/lab/native/`; implementation and test details are in
[the findings](lab/FINDINGS.md#animations-and-paint-without-swiftc).
Installed state, environment key paths, arbitrary composition and the three
older apps below have not yet moved to this backend.
It targets Apple ARM64/macOS 26+ and has been runtime-tested on macOS 27.0.1.
The build needs Zig and Apple's SDK/link libraries; the optional oracle needs
Swift 6.2+. Python runs the checks.

## Swift ABI + SwiftUI lab

Three standalone prototypes use a Zig state engine, native SwiftUI components,
and Swift `@main App` entry points generated by a pure Zig program:

- **ZwiftTodo** — checkboxes, typed drag/drop reordering, filters and deletion; Zig callbacks feed Swift Observation.
- **ZwiftEditor** — a native text editor with UTF-8 open/save and live statistics; `@State` stores reducer snapshots.
- **ZwiftBrowser** — WebKit with an address bar, back/forward, reload/stop and navigation errors; a custom `DynamicProperty` bridges a Zig-owned address to `Binding`.

Two experimental paths now work together:

- **Native ABI emitter:** a Zig registry generates ten ARM64 specializations: `Text` from literals/owned strings, `State<UInt64/Bool/Double/String>`, `Environment<Bool/Double>`, `Binding<Bool>.constant`, and a four-word value.
- **Typed Swift view generation:** Zig definitions generate concrete SwiftUI view structs with checked fields, state, environment, bindings, actions, branches and keyed `ForEach`. All three apps use generated controls; their state panel uses native Zig ABI factories.

In these three harnesses, Swift still compiles the generated views and supplies SwiftUI protocol metadata,
key paths and lifecycle machinery. Platform adapters remain handwritten Swift. View definitions use small typed Zig
helpers; generator errors identify the failing view and field.

```sh
./scripts/zig build lab                 # three apps in zig-out/
./scripts/zig build lab-test            # Zig + mounted SwiftUI + WebKit integration
./scripts/zig build lab-launch-test     # exercise all three real Swift App entry points
./scripts/zig build lab-abi-check       # verify all ten Swift ABI signatures
./scripts/zig build lab-generate        # inspect generated Swift, assembly and manifest
./scripts/zig build lab-bench           # optimized ABI/view/model benchmarks
./scripts/zig build run-lab-Todo
./scripts/zig build run-lab-Editor
./scripts/zig build run-lab-Browser
```

The launcher uses installed Zig 0.16.0, or downloads the official release into
`.zig-cache/toolchains/` and verifies its pinned SHA-256. `ZIG=/path/to/zig`
selects an existing 0.16.0 compiler. Your global Zig stays unchanged.
With 0.16.0 on `PATH`, ordinary `zig build …` works too.

The lab requires **Apple Silicon, macOS 26+, Swift 6.2+**, Command Line Tools (or
Xcode), and Python 3 for the checks/bootstrap. Tested here with Swift 6.2.3 on
macOS 27.0.1. The support policy is the current major macOS release and its
immediate predecessor, pinned in `lab/platform.zig`. Runtime testing on macOS
26 remains outstanding.

Read [the findings and alternatives](lab/FINDINGS.md) for ABI details, typed view examples,
measured performance, verification and remaining prototype limitations.
Generated declarations are in `zig-out/lab/generated/`; screenshots are in
`zig-out/lab/screenshots/` after the tests. Benchmark samples are written to
`zig-out/lab/performance.json`.

## Original examples

The original todo app still has two frontends:

- **Zig** — native AppKit UI built entirely in Zig via Objective-C runtime bindings
- **Swift** — SwiftUI frontend

Both produce standalone `.app` bundles.

## Requirements

- macOS 13+
- [Zig](https://ziglang.org/download/) 0.16.0 (or use `./scripts/zig`)
- Swift toolchain (ships with Xcode or Command Line Tools) — only needed for the Swift version

## Build & Run

```
zig build            # builds both app bundles
zig build app-zig    # builds TodozZig.app (Zig + AppKit)
zig build app-swift  # builds TodozSwift.app (SwiftUI)
zig build run-zig    # build and open TodozZig.app
zig build run-swift  # build and open TodozSwift.app
```

App bundles are output to `zig-out/`.

### Tests

```
zig build test
```

## Regenerating bindings

The AppKit/Foundation Zig bindings are pre-generated and checked in. To regenerate them (e.g. for a new SDK version):

```
python3 scripts/gen_framework.py AppKit
python3 scripts/gen_framework.py Foundation
```

Requires macOS with Command Line Tools or Xcode installed.
